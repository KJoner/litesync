# LiteSync — Obsidian 私有同步插件（中文文档）

配合 [LiteSync Server](https://github.com/KJoner/litesync-server) 使用的 Obsidian 同步插件。
笔记同步到**你自己部署的服务器**：端到端加密、版本历史、自动三方合并，
没有第三方云、没有账号、没有遥测。

桌面与 **iOS / Android 移动端**通用（需要 Obsidian 1.13+）。
[English documentation →](README.md)

> **必须先有一台 LiteSync Server**——一个 Docker 容器，一行命令部署完成
> （1 核 / 256MB 的 VPS 足够）：<https://github.com/KJoner/litesync-server>

## 快速上手

### 第一台设备

1. 在 VPS 上一键部署服务器（完成后会输出 API Token）：

   ```bash
   bash <(wget -qO- https://raw.githubusercontent.com/KJoner/litesync-server/master/scripts/litesync-install.sh)
   ```

2. Obsidian 安装本插件 → 设置里填 **Server URL** 和 **API Token**
3. 点 **测试连接**。如果远端仓库还是空的，会当场给出三个选项：
   - **关闭**——什么都不做；
   - **立即同步**——初始化远端并开始首轮同步；
   - **添加 E2EE 并立即同步**——先设加密密码再初始化。远端是空的，
     **没有迁移过程：首次上传就是密文，明文从头到尾不经过服务器**。
4. 远端已有内容时不弹此对话框，而是进入接入向导（见下）。

### 第二台及以后的设备

不需要再输一遍服务器配置：

1. 已配置的设备上：设置 → **设备与迁移** → **添加新设备**
2. 新设备安装 LiteSync 后用系统相机扫码（或打开配对链接）→
   **在 Obsidian 中打开** → 确认导入
3. 启用了 E2EE 的话，手动输一次密码（密码**永不随配对包传输**）
4. 接入向导里选「**从远端恢复**」即完成

配对包在本机加密后上传，5 分钟过期且一次性，服务器只见密文。
新设备本地已有笔记时，向导会改为提供**安全合并**——不会静默覆盖，
也不会永久删除任何东西。

## 安装

Community Plugins 上架前先手动安装：

1. 从 [Releases](https://github.com/KJoner/litesync/releases) 下载
   `main.js`、`manifest.json`、`styles.css`
2. 复制到 `<你的Vault>/.obsidian/plugins/litesync/`
3. 设置 → 第三方插件中启用 **LiteSync**

## 设置项

### 服务器

- **Server URL**：例如 `https://sync.example.com`（本机开发可用 `http://localhost:8080`；
  非本机的 `http://` 会被硬性拒绝，Token 与笔记绝不走明文 HTTP）
- **API Token**：与服务器 `OBSYNC_TOKEN` 一致，保存在 Obsidian
  SecretStorage（不进 `data.json`）
- **测试连接**：验证地址与 Token；远端为空时给出上面的三选项
- **设备名称**：用于冲突文件命名（如 `Project.conflict-MacBook-20260808-001500.md`）
  与服务器上的设备列表

### 同步

- **自动同步**：文件变化后防抖上传 + 定时拉取
- **同步间隔**：15 秒 / 30 秒 / 60 秒 / 2 分钟 / 5 分钟 / 关闭定时
  （移动端定时器只在前台运行，最低 60 秒）
- **同步 Obsidian 配置目录**：默认关闭；开启后 workspace 文件与本插件目录
  仍然永远排除；**移动端始终不同步配置目录**
- **忽略规则**：每行一个 Glob，默认 `.trash/**`、`.DS_Store`、`Thumbs.db`
- **立即同步**：手动触发一次完整同步

### 设备与迁移

- **添加新设备**：生成一次性加密配对二维码 / 链接
- **导入配对链接**：粘贴在其他设备上生成的链接
- **重新运行接入向导**：重新选择本设备与远端的接入方式

### 加密与隐私

「端到端加密」「实验功能」「隐私增强」三组设置的完整说明见下方
[端到端加密](#端到端加密)与[隐私增强](#隐私增强可选默认关闭)两节。

### 调试

- **Debug 日志**：在开发者控制台输出同步细节

## 命令

命令面板（`Ctrl/Cmd+P`）搜索 LiteSync：

| 命令 | 作用 |
|---|---|
| 立即同步 | 完整跑一轮同步；**不受时间混淆延迟影响** |
| 文件版本历史 | 当前笔记的历史版本（也可右键文件 →「LiteSync: 版本历史」） |
| 解决同步冲突 | 打开冲突解决器 |
| 解锁端到端加密 | 输入 E2EE 密码解锁 |
| 管理分享 | 列出并撤销已创建的分享 |
| 设备列表 | 查看服务器上已注册的设备 |
| 升级加密信封 LSE1 → LSE3 | 把存量密文批量升级到当前信封 |
| 加密路径与文件名 | 实验功能（RC），需先在设置里开启 |
| 平台兼容性自检 | 在这台设备上实测文件系统语义（见[平台限制](#平台限制)） |

## 同步行为

一次完整同步：**拉取远端变更 → 扫描本地变化 → 推送队列 → 对齐游标**。

- 状态栏：`✓ Synced` / `↻ Syncing` / `! N Conflicts` / `× Offline` / `🔒 Locked`
- 离线时修改进入待同步队列，本地编辑完全不受影响；恢复后按
  5s → 15s → 30s → 60s → 2min → 5min 退避自动重试
- 远端删除本地文件时移入回收站（system trash），**不做永久删除**；
  回收站失败时保留文件并标记，绝不静默丢失
- 改名是一次元数据更新：内容零重传，版本历史与对象身份跨改名连续
  （2GB 的视频改个名不会重新传 2GB）
- 服务器变更日志被裁剪（长期未开机的设备）时自动走 **snapshot 全量对账**
  重建游标，不漏任何删改
- 设备凭据被撤销时会弹出**常驻通知**并停止无意义重试，重新接入后自动恢复
- 同步状态（deviceId、lastSequence、hash 缓存、未解决冲突、分享密钥）
  保存在插件目录 `state.json`，与设置分离，永远不会被同步出去

## 移动端（iOS / Android）

网络层（`requestUrl`）、加密（Web Crypto）、文件访问（`vault.adapter`）
全部使用跨平台 API，`npm run test:mobile` 强制审计不引入 Node/Electron 依赖。
移动端专属行为：

- **同步时机**：启动 / 文件修改防抖 / 前台定时（最低 60 秒）之外，
  **切回 App 时自动补同步**（iOS 后台定时器会被系统暂停）
- **删除安全**：远端删除 → 移入 vault 内 `.trash`；失败时保留本地文件
  并记录待手动删除（绝不永久删除，也不会被重新上传）
- **`.obsidian` 不同步**：无论设置如何（桌面与移动界面配置差异大）
- **大文件警告**：>50MB 文件同步时提示内存占用（不跳过，保证一致性）
- **界面**：冲突解决器等在窄屏自动纵向堆叠，按钮满足触控尺寸

## 冲突处理：三方自动合并

两端同时修改同一个 `.md` 文件时：

1. **自动三方合并**：以共同祖先版本（服务器历史）为 Base 做 diff3，
   修改不重叠时自动合并上传，无需任何弹窗
2. **结构化冲突 → 解决器**：同一区域两边都改时进入 pending conflict
   （暂停该文件自动同步），状态栏 `! N Conflicts`，点击或运行
   「解决同步冲突」：LOCAL / REMOTE 双栏对比，逐冲突段
   `Use Local / Use Remote / Use Both`，合并结果可直接编辑后保存；
   保存时远端又变化会重新加载再合并，绝不绕过 revision 校验
3. **keepBoth 兜底永远保留**：二进制、`.canvas`、Base 已被清理、
   引擎任何异常 → 回退「保留两个版本」（`xxx.conflict-设备名-时间戳.md`），
   任何情况下不丢任何一方内容

## 版本历史

- 命令「文件版本历史」或右键文件 →「LiteSync: 版本历史」
- 每个版本可**对比**（逐行 diff）、**恢复**（旧内容作为新版本上传，
  历史线性可追踪）、**另存副本**（`xxx.rev-N.md`）
- 保留策略在服务器端配置（默认 Markdown 90 天 / 100 版，附件 30 天 / 10 版）

## 端到端加密

设置页 → 端到端加密 → **启用端到端加密**：

- 密码经 PBKDF2-SHA256（600k 迭代）派生 KEK，解锁随机 Vault Master Key；
  服务器只保存**加密后的** vault key 副本，密码与明文密钥永不上传
- 文件以 AES-256-GCM 加密（**LSE3** 信封：AAD 绑定 vaultId + 密钥世代 +
  fileId + 内容世代），服务器只见密文
- 迁移：全部文件重新加密上传 → **下载回验（解密 + hash 一致）后**才清理
  服务器明文历史；中断可重跑（已加密文件自动跳过）
- 空仓库首次配置时可直接选「添加 E2EE 并立即同步」，**不经历迁移**
- 新设备：填好地址与 Token 后运行「解锁端到端加密」输入密码
- 未解锁时状态栏 `🔒 Locked`，同步暂停，本地编辑不受影响
- ⚠️ **密码丢失 = 服务器数据永远无法解密**；暂不支持关闭 E2EE 或改密码

### 凭据安全：信任此设备

**E2EE 密码永远不持久化**——记住的是「设备已授权」，不是密码：

- ☑ **信任此设备**：解锁后把 VMK 用随机设备密钥包装保存，之后启动自动解锁
- **拆分包装**：设备密钥存 `data.json`（vault 内），包裹后的 VMK 存
  Obsidian SecretStorage（vault 外）——单独复制任何一份都无法还原密钥
- 服务器密钥轮换后设备信任自动失效
- 设置页提供 **忘记此设备**（下次需重新输密码）

### 每台设备一份最小权限凭据

根 Token 只用于第一台设备的注册与服务器管理：首轮同步后自动换发**设备凭据**，
根 Token 此后不再留在任何设备上。丢失的设备可以在服务器上单独撤销，
不影响其他设备，也不需要轮换任何密钥。

### 路径与文件名加密（实验功能 / RC，默认关闭）

开启后可运行「加密路径与文件名」，把服务器上的路径全部替换为随机伪名，
真实路径改存加密元数据。迁移可续跑、删除屏障完整保留，但
**最后的擦除步骤不可逆，且迁移前的备份里仍然含有明文路径**——
请只在测试 Vault 或有完整备份的副本上使用。动手前先在服务器上执行
`obsync migration preflight`（会检查有没有设备还没升级）。

## 分享

右键文件 →「LiteSync: 分享此文件…」：

- 每个分享生成**独立随机 Share Key**，只加密该分享对象（与 VMK 完全无关）
- 笔记里**内嵌的图片会一起加密打包**（总预算 64MB，超出的单张跳过并提示），
  查看页在浏览器本地解密渲染；服务器看到的仍然只是一个密文 blob
- **Share Key 在链接 `#` 片段中，不会发给服务器**
- 有效期：7 / 30 / 90 天 / 永久，或「自定义…」（分钟 / 小时 / 天）
- 命令「管理分享」可随时**撤销**（不影响原 Vault）；服务器运维页也可以撤销
  或设置新的到期时间
- 查看页禁止加载任何外部资源（CSP），笔记里的外链图片不会把查看者 IP
  报给第三方
- 高安全场景可用服务端仓库里的 `viewer/litesync-viewer.html`：
  自包含单文件查看器，保存到本地后即使服务器被攻陷也无法替换它

> 0.17.0 之前创建的分享不含附件，图片位置仍是文件名文字——重建一次分享即可。

## 多用户（v0.18，邀请制）

一台服务器可以装下几个**互不可见**的仓库。管理员在网页端「用户管理」
生成一次性邀请链接（随机 32 字节后缀、默认 24 小时过期、可撤销）；
对方打开链接、起个用户名，就能拿到自己的 API Token 和分步接入教程。

- **数据完全隔离**：文件、变更流、历史、分享、设备、E2EE 密钥文档全部
  按用户仓库分开，由自动化越权测试矩阵盯着
- 管理员看得到用户名、设备数与用量，**拿不到任何人的 API Token**
  （服务器只存哈希）或 E2EE 密码（从不上传）
- 用户可被禁用（数据保留、设备立即失效）或删除（输入用户名确认，不可逆）
- API Token 丢失**无法找回**——没有找回流程就没有社工攻击面；
  只能请管理员删除后重新邀请（数据清空）。请像对待密码一样保存它
- 运维/设置/用户管理页仅管理员可见；普通用户网页端只有自己的笔记和
  「账户」页

## 单用户多仓库（v0.19）

一个 API Token 名下可以有多个**互相隔离**的远端仓库（工作/个人/项目各一个）：

- 接入向导第一步选择仓库：已有仓库（远端覆盖本地 / 两端合并）或**新建**
  （本地文件初始化上去）；名下只有一个仓库时同样显示（预选它）——
  「新建仓库」的入口就在这一步
- **新仓库强制 E2EE**：空远端的初始化必须先设端到端加密密码，首次上传
  即密文——没有「先明文、事后迁移」的路径；既有明文仓库不受影响
- 设置页可查看**当前仓库**（名字与远端文件数）并就地重命名（只改显示名）
- **切换仓库 = 重新运行接入向导**：会作废本设备的同步记录（本地笔记保留），
  然后按所选方式全量对账——没有轻量开关，这个重量是刻意如实呈现的
- 一个 E2EE 密码可以用于多个仓库，但每个仓库是独立密钥文档与独立盐——
  一个仓库的密钥材料泄露不波及其他；各仓库分别解锁
- 切换或新建需要账户的 API Token；设备凭据只绑定单一仓库（被盗设备
  不能横向进入你的其他仓库）
- 网页端右上角可切换仓库查看

## 重置 API Token（v0.18）

怀疑 Token 泄露（而 E2EE 密码没泄露）时，在网页端「账户」页一键重置：
旧 Token 立即作废、该账户全部设备凭据同时撤销、其他网页会话全部下线。
每台设备只需在插件设置里填入新 Token → 点「测试连接」，同步自动恢复——
不重跑向导、不全量对账，本地笔记、历史与加密密钥都不受影响。

- **E2EE 密码是重置的硬关卡**：启用 E2EE 的仓库会在解锁时自动登记一个
  由加密密钥派生的重置凭证（服务器只存哈希）。只拿到 Token 的攻击者
  派生不出它，抢不走重置权、锁不了你的门
- 未启用 E2EE 时没有这道关卡：任何持 Token 者（含攻击者）都能重置——
  这是启用 E2EE 的又一条理由
- 服务器 shell 兜底：`obsync token reset`（忘了 Token 或凭证被抢注时）
- **重置追不回已泄露窗口内被下载的密文**——那部分只由 E2EE 密码强度保护。
  重置是止血，不是时光机

## 隐私增强（可选，默认关闭）

E2EE 挡住了**内容**，没挡住内容之外的东西。这两项分别处理其中两样，
成本与做不到的部分都写在设置页里：

### 混淆文件大小

精确字节数本身就是信息：已知文档的大小命中即确认；同一文件的大小序列
（1832 → 1847 → 1901）画出的是编辑节奏。开启后密文被填充到桶边界，
服务器只看得到大小区间。

- 成本：单个对象最坏多占 **12.5%**；小于 4KB 的对象一律按 4KB 计
- 仓库内去重不受影响（填充在密文内部）
- 只影响开启之后新写入的内容，已有文件在下次修改时才转入新信封
- 可以只对高敏目录开启（填写路径前缀，每行一个）

### 混淆同步时机

请求节奏就是打字记录：作息、时区、工作日与假期、此刻是否醒着，
都能从时间戳序列推断。开启后上传对齐到时间窗口发车（默认 5 分钟）并加抖动，
上报的文件修改时间也按粒度向下取整。

- 代价：同步被推迟平均约一个窗口、最多约两个窗口，**跨设备可见延迟与
  冲突窗口都会随之变长**
- 「立即同步」命令不受影响
- **做不到什么**：它降低的是分辨率，不隐藏「你在某个窗口里到底有没有编辑」——
  那需要持续发送掩护流量。本项目不做掩护流量，也不暗示自己做了。

## 已知限制与剩余威胁

把 LiteSync **不**保护什么写清楚，是设计的一部分。以下内容对应 v0.18.0。

### 恶意或被攻陷的服务器还能做什么

E2EE 意味着服务器无法**读**你的笔记，不意味着它在其他方面可信。
客户端会检测并硬失败于以下攻击：

| 攻击 | 能检测？ | 靠什么 |
|---|---|---|
| 把别人的内容当成你的文件返回 | ✅ | fileId 必须与请求的对象一致 |
| 重放某个文件的旧版本 | ✅ | 内容世代不允许后退 |
| 重放旧元数据（例如撤销一次改名） | ✅ | 认证过的 metaGeneration 不允许后退 |
| 同一世代给出两份不同元数据 | ✅ | 元数据指纹不符 = 分叉，停止同步 |
| 降级加密信封 | ✅ | 仓库级信封下限，信封只升不降 |
| 用构造的元数据塞入路径穿越文件名 | ✅ | 解密后的路径落盘前先校验 |
| 把整个仓库回滚到旧备份 | ✅ | repoEpoch 变化强制走显式恢复合并 |
| 给设备 A 和设备 B 看不同的仓库状态 | ✅ | 设备签名 checkpoint，分叉时停止同步而不是选一边 |
| 你已同步之后再回滚到更早状态 | ✅ | 信任锚只向前移动，每个 checkpoint 必须接上你见过的链 |
| **扣住一个你从未见过的文件** | ❌ | 没见过的东西没有本地锚点，服务器也没有「给全了」的证明 |

最后一行是诚实的**结构性**缺口，不是没做的功能。准确的说法是：

> 恶意服务器无法在不被发现的情况下回滚或调包你已经同步过的内容，
> 也无法长期给你的不同设备看不同的仓库状态。但它仍然可以拒绝服务，
> 也仍然可以藏起一个你从未见过的文件。

签名 checkpoint 由**你的设备**签发，服务器永远不参与签名。新设备不信任
服务器给出的第一份清单——它的信任锚通过设备配对传入，密钥只走链接的 `#fragment`。

### 服务器仍然能看到的元数据

| 元数据 | 默认 | 开启隐私增强后 |
|---|---|---|
| 对象精确大小 | 可见 | 只剩桶区间（最坏多占 12.5% 空间） |
| 编辑时间点 | 近实时，每次保存一条 | 只知道落在哪个窗口 |
| 存储的 mtime | 精确 | 按粒度向下取整 |
| 某个窗口内是否编辑过 | 可见 | **仍然可见**（不做掩护流量） |
| 对象数量、访问模式 | 可见 | 可见 |
| 路径与文件名 | 可见 | 启用上面的 RC 路径加密后只剩伪名 |

大小填充只覆盖**内容**信封；元数据信封与分享名信封尚未填充——它们很小
且长度分布集中，但这是一个已知缺口。

### 平台限制

- 无法保证原子替换的平台上，覆盖已有文件会**自动退化**为把新版本存在旁边，
  而不是冒险写半个文件。目前实测过的平台（Windows、Linux、macOS、iOS、
  Android）**都**支持原子安装，所以这条是安全网而非日常行为。插件在运行时
  实测而不是假设——运行「**平台兼容性自检**」可以看到你这台设备的结果。
- `Note.md` 与 `note.md` 一律视为**同一个文件**，`café.md` 无论 NFC 还是 NFD
  也是同一个文件。这是刻意的，而且有实测支撑：真机上 **iOS 大小写敏感且做
  Unicode 归一，Android 恰好相反**。按本地平台判断会让这两台设备对「两个名字
  是否撞车」给出相反答案，然后互相覆盖。代价是即使系统允许，你也不能同时保留
  `Note.md` 和 `note.md`；收益是没有任何设备会静默覆盖另一台的内容。
- 网络磁盘与云同步目录（Dropbox、OneDrive、iCloud Drive）**不支持**作为
  Vault 位置——两个同步器写同一批文件会互相破坏状态。

### 规模

正式声明并按此测试的上限见
[服务端 README](https://github.com/KJoner/litesync-server#正式支持规模)：
单仓库 20 000 文件、单文件 100MB、最长离线 90 天。超出这些数字不是坏掉了，
只是没有被验证过。

## 开发

```bash
npm install
npm run build        # 类型检查 + 打包，产出 main.js
npm run lint         # eslint-plugin-obsidianmd 推荐规则
npm test             # 289 条测试（按 tests/ 目录自动发现）
npm run test:mobile  # 移动端 CI：Node/Electron 依赖审计 + 构建 + 全部测试
npm run check:adr    # 每个 ADR 都被它约束的代码引用
npm run check:inv    # 每条不变量（INV-xx）都有标注的测试
npm run dev          # watch 模式
```

CI 在 Linux / macOS / Windows 三个平台跑全量测试——本插件依赖的文件系统语义
（大小写、Unicode 归一、原子替换）本身就因平台而异。移动端那一格由插件内的
「平台兼容性自检」命令在真机上取证，因为 Obsidian Mobile 跑不进 CI runner。

架构与开发约定见 [AGENTS.md](AGENTS.md)。
本仓库开发用：`scripts\dev-deploy.ps1` 一键构建并部署到测试 Vault。
