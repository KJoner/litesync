## 新能力（主要在服务端与网页端）

### 重置 API Token

怀疑 Token 泄露时，在网页端「账户」页一键重置：旧 Token 立即作废、该账户
全部设备凭据同时撤销、其他网页会话全部下线。每台设备只需在插件设置里填入
新 Token → 点「测试连接」，同步自动恢复——**不重跑向导、不全量对账，
本地笔记、历史与端到端加密密钥都不受影响**。

- **E2EE 密码是重置的硬关卡**：已启用端到端加密的仓库会在解锁时自动登记
  一个由加密密钥派生的重置凭证（服务器只存哈希）。此后只拿到 Token 的
  攻击者无法抢先重置把你锁在门外——他派生不出这个凭证。
- 服务器 shell 兜底：`obsync token reset`（忘了 Token、或凭证被抢注时用；
  `--from-env` 可回到环境变量的值）。
- `OBSYNC_TOKEN` 环境变量从此只是**首次初始化的种子**：网页重置过之后
  以数据库为准，重启不会把旧 Token 变回来（启动日志会明确提示这个状态）。
- 如实说明：重置不能追回泄露期间已被下载的密文——那部分只由 E2EE 密码
  强度保护；未启用 E2EE 的仓库没有凭证关卡，任何持 Token 者都能重置。

### 多用户（小范围，邀请制）

服务器从「一个人的仓库」变成「几个人各自独立的仓库」：

- 管理员在网页端「用户管理」生成**邀请链接**（32 字节随机后缀、一次性、
  默认 24 小时过期、可撤销）；
- 受邀者打开链接，起个用户名即完成注册：拿到自己的 API Token 与全中文
  分步接入教程（教程会强烈建议开启 E2EE，并说明不开的后果）；
- **数据完全隔离**：每个用户一个独立仓库——文件、变更流、历史、分享、
  设备、E2EE 密钥文档全部按仓库分开，由自动化越权矩阵测试盯着；
- 管理员看得到用户名、设备数与用量，但**拿不到任何人的 API Token**
  （数据库只存哈希）或 E2EE 密码（从不上传）；
- 用户管理支持禁用（撤销设备凭据 + 踢下线，数据保留）与删除（输入用户名
  确认，数据、历史、分享一并清除并回收磁盘）；
- 运维、设置、用户管理页仅管理员可见；普通用户网页端只有自己的笔记
  与「账户」页（重置自己的 Token）。API Token 丢失**无法找回**（刻意设计：
  没有恢复流程就没有社工攻击面），只能由管理员删除后重新邀请。

## 插件侧改进（0.18.0）

- 「测试连接」在凭据失效停机后验证成功时**自动恢复同步**，不再出现
  「连接成功但状态栏一直 Offline」；
- 凭据被撤销的常驻提示在恢复后**自动消失**；文案不再建议「配对」
  （那会触发一次不必要的全量对账），并区分「Token 已被重置/设备被撤销」
  与一般认证失败；
- Token 输入改为停顿/失焦提交，输入过程不再打出半截 Token 的假 401；
- E2EE 解锁后自动登记重置凭证（见上）。

## 升级

1. 先升服务端：`docker compose pull && docker compose up -d`
   （数据库迁移自动完成，全部为加列/新表，可直接回滚到 v0.17.x）
2. 再升各设备插件（不急，0.17 插件完全兼容）
3. 已启用 E2EE 的设备升级后第一轮同步会自动登记重置凭证；网页解锁同样会

回滚提示：若已在网页重置过 Token，回退到 v0.17.x 后生效的是 `.env` 里的
旧值；已创建的多用户在 v0.17.x 下无法访问（升级回来即恢复）。
