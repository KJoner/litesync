**公开化第一版：严格会话解锁、先核对再连接的连接链接、重新整理的设置页与中文界面、本地完整替换远端（验收阶段，默认关闭）。**

- 协议仍是 v6。
- 连接链接 v2（先核对、断网可续传）需要服务端 v0.20.0。在旧服务端上，插件会自动退回原来的配对流程，并在界面上说明「无法在导入前核对仓库」。

---

## 默认改为严格会话解锁

- **新安装不再保存任何能自动解锁仓库的材料。**
  - 仓库密码只在本次运行中使用。锁定、切换仓库或重启 Obsidian 之后，需要重新输入。
  - 本设备只保留访问密文用的设备凭据。状态卡把「设备已授权」和「仓库已解锁」分成两行显示。
- 「信任此设备」改名为 **本设备自动解锁（可恢复密钥持久化）**。
  - 它只在「高级与诊断」里，默认关闭。开启前会写明它保存了什么、防不住什么。
  - 解锁和启用加密的弹窗不再有勾选框。
- **从 0.19 升级的设备不会被打断。**
  - 本次运行照常自动解锁，设置页显示「旧设备信任待迁移」。
  - 迁移时先用仓库密码证明能解开**同一把**密钥。忘了密码，也可以在这台仍能解锁的设备上为同一把密钥设新密码，绝不会生成新密钥。
  - 确认待同步的修改已经妥善保存之后，才清除旧材料。验证之前什么都不删。清理中途崩溃的话，重启后会把清理做完，不会重复动作。
  - 每一步落盘都会读回核对。data.json 只读或磁盘写不进去时，迁移停在动手之前，不改服务器、不清材料。
- 如实说明：锁定 LiteSync 不会加密 Obsidian 已经保存在本地的 Markdown 和附件。锁定只暂停本设备的同步与解密，本机笔记仍然可以阅读和编辑。
- 这些会话状态带有代次：在锁定、切换仓库或更换连接之后，晚到的解锁结果一律作废，绝不会把上一个仓库的钥匙装进新的会话。

## 连接链接 v2：先核对，再连接

- 未连接时，设置首页只有两个入口：**粘贴连接链接**、**打开网页注册或登录**。手工填 Server URL 和 API Token 收进了「高级与诊断 › 手动连接」。
- 导入链接时**先只读**取配对包。打开链接、刷新落地页、链接预览都不会用掉它。
- 配对包在本机解密后，先展示**服务器、账号、仓库、信任方式和有效期**，你确认之后才兑换。
- 兑换前先把兑换编号落盘。断网或崩溃之后用同一个编号重试，服务端返回同一份结果：不会多建一台设备，也不会卡在「链接已用掉却没拿到凭据」。超过 10 分钟作废，并提示重新生成。
- 以下情况绝不回落到默认仓库或旧的长期 Token 包：
  - 服务端返回的仓库和核对过的不一致：这份凭据一个字节都不用。
  - 配对包需要插件不认识的能力：拒绝导入，提示升级。
- 旧版 v1 配对包（含长期 Token）只做受限的兼容导入，并要求你确认风险。
- **连接新设备**（原「添加新设备」）为当前仓库申请一次性授权，包里写明仓库和账号。
  - 只有本机持有已验证的检查点锚，并且它和当前 repoEpoch 一致时，才把锚交给新设备，界面显示「继承发行设备已验证的检查点」。否则如实写「首次信任」。
  - 新设备在**写入任何内容之前**核验这个锚：仓库身份、repoEpoch、可信水位，服务器仍持有锚检查点，之后的链是合法延伸。
  - 核验不通过就停下，给出「重新配对（推荐）」和「读过风险说明后改为首次信任」两条路，绝不静默降级。
- 连接链接已经写明仓库、并且和服务器的当前仓库一致时，接入向导不再让你重选。顶部会写明目标仓库，并提供「选择其他仓库…」。

## 设置页与界面

- **设置首页是一张状态卡，下面是五个任务子页。**
  - 状态卡：仓库、设备授权、仓库解锁、密钥保存方式、最近同步、冲突，加上**唯一**一个主按钮（连接仓库 / 完成接入 / 解锁仓库 / 立即同步）。
  - 五个子页：连接与设备、同步选项、仓库密码与锁定、恢复与帮助、高级与诊断。用的是 Obsidian 1.13 原生的设置子页，沿用宿主样式。子页入口上会显示当前值和提醒，例如需要重新连接、有冲突、已锁定、有待处理的作业。
  - 设置项的键、存储和行为都不变。旧名字（「同步间隔」「设备列表」「添加新设备」「忘记此设备」等）在设置搜索里仍然能找到新位置。
- **状态卡如实说明情况。**
  - 最近一轮同步没完成时，写「未完成：原因（上次成功：…）」。
  - 自动同步关闭、有待恢复的作业时，各多一行说明。
  - 连接、完成接入、同步或设备被撤销之后，设置页当场更新，不用离开再进来。你正在输入框里输入时，等焦点离开再刷新。
- **状态栏改用中文**，和状态卡同一套说法：
  - 正常时显示 ✓ 已同步 / ↻ 同步中 / ! N 个冲突 / 🔒 已锁定；
  - 同步停下时分清「离线」「需要重新连接」「同步暂停」三种情况，原因放在悬停提示里。
- **已连接设备**：显示设备名、本设备、连接时间和最近活动；设备 ID 和权限收进「技术详情」。撤销设备授权在网页上的「账号与设备」里做，不再给出要服务器根 Token 的 curl 命令。
- **手机上只显示真正生效的设置**：「检查云端更新」只列出 60 秒或更长的频率；「同步 Obsidian 配置目录」在手机上说明「此设备不支持」。
- **冲突窗口**：
  - 全部改为中文：保留本机段落 / 保留云端段落 / 依次保留两段 / 保留两个文件，并显示「已处理 X / N 处冲突」。
  - 多处冲突逐处处理，也可以切回「显示全部冲突」。
  - 手机上用「本机 / 云端 / 结果」三个标签页对照全文。
  - 有没保存的选择或手工编辑时，关闭前会先确认。
  - 保存时远端又变了，你手工编辑的合并结果会留下来供你取用。
- **版本历史**：显示「版本 N」，说明「恢复」不会删除任何版本，对比窗口带图例，按钮的读屏名称带上版本号。

## 高级恢复：用本地完整替换远端（验收阶段，默认关闭）

- 作用：远端在同步范围内变成本设备的样子。不同的以本地为准覆盖，远端多出来的删除（留下 tombstone），本地多出来的上传。
- **执行入口默认关闭**：要在「高级与诊断 › 高级恢复」里显式打开（标注「验收阶段」）。
  - 关闭时，只读的差异预览照常可用。
  - 已经开始的作业仍可以诊断、放弃或回滚。
- 流程：
  1. 先生成完整的差异预览（只读）。
  2. 输入仓库名确认。
  3. 把将被覆盖或删除的远端原始字节保存为恢复点，逐个读回、解密校验。
  4. 逐个对象带版本前提写入，执行前和每个动作前都复核本地前置条件与同步许可。
- 预览之后远端或本地有变化，或者期间出现别的设备的写入，作业立即暂停，只能重新预览。断网之后可以续跑，不会重复写入。
- 完成后可以生成**回滚**：把远端恢复到替换之前（新 revision，不回退计数器），被替换掉的本地副本会先备份。
- 远端为空时，本功能直接拒绝，并引导你去「用本地初始化空仓库」。

## 修复

- **用网页新建的加密空仓库现在可以直接接入。** 以前新设备解锁之后，仍被要求再设一个新密码，然后卡在「远端仓库已不是未初始化状态」。现在用现有密钥接入：空本地直接完成，本地已有笔记就加密上传。
- 首次接入选「合并」时，本地独有、但远端曾经删过的同名文件会卡在 revision 冲突。现在先显式恢复原对象（身份和历史连续），再上传。
- 路径加密的仓库里，恢复一个删过的文件之后再改名，不再退化成「新建一个、删除原来的」。其他设备也不会因此误判同世代分叉。
- Windows 和 macOS 这类大小写不敏感的文件系统上，只改了大小写的文件经过完整替换之后，第一轮同步不再把它当成冲突，另存一份副本。
- 完整替换在窗口里中断后，「继续执行」不再卡在「作业状态不允许确认」。在接入向导里执行到一半被强杀，重启后已完成的部分也不再被当成旧账作废。
- 账号中心暂时无法确认登录状态（503 `IDENTITY_UNAVAILABLE`）时，按可重试处理：
  - 本地修改和游标保留，重试不早于服务器给的 Retry-After；
  - 状态写「账号中心暂时无法确认你的登录状态，稍后自动重试；本地修改已保留」，不会要求你重新连接。
- 服务器（0.20）开启账号存储配额后，用完时提示「配额用完」，不再误报成「超过服务器大小限制」。文件照常留在本地和待上传队列里，额度恢复后自动继续，提示每 10 分钟最多一次。

## 升级说明

- 插件侧没有数据迁移。
  - data.json 新增 `keyPolicyVersion`、`trustMigration`、`replaceRemoteEnabled`；
  - state.json 新增 `pendingPairingTrust` 与 `replaceJob`。
  - 旧版本会忽略它们。
- 降级到 0.19.x：已经完成严格模式的设备需要输入一次密码，因为 0.19 会按旧默认重新保存信任材料。
- 「本设备自动解锁」：从 0.19 升级的设备保持原状，直到你完成迁移；新安装默认关闭。
- 命令「解锁仓库」的命令 ID 没有变，已绑定的快捷键继续有效。
